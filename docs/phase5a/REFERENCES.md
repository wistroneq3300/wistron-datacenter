### 2012 全棟照片的可見樓層節奏

為避免把明顯不同的量體留在 Draft 標籤之下，本輪另從 R05 PDF **直接提取原始嵌入 JPEG**，沒有 AI 放大或生成細節。原照為 677×373，研究檔 `../phase5-work/references/wistron-2012-page37-extract-Im0.jpg`；3200px PDF 頁面渲染不會增加這張原照的細節。

- 主玻璃轉角自屋頂頂簷下方至石材基座上方，可清楚數出 **4 個主要玻璃樓層帶**，其間由深色外挑水平框／帶分隔。每層內部的較細橫框不能再算成另一層。
- 下方可見 **2 個石材基座／開窗層**：玻璃轉角正下方的一層橫窗，及接地面的一層開口。地面部分被植栽遮擋；不推論地下樓層或不可見夾層。
- 因此照片支持的是 **4 個上部玻璃層＋2 個石材基座層，合計約 6 個主要樓層節奏**。它不支持原模型的 9 層外觀。這個觀察應用來修正可見外觀，不是對法定／結構樓層數的認證。
- 右端獨立玻璃量體也能對應 **4 個上部玻璃層**。兩玻璃量體之間的右側石材翼部，每個上部樓層可辨 **5 個主要窗洞**，其中含較窄洞口；這是洞口數，不是玻璃分格／窗扇總數，也不是等寬格網。
- 主轉角的上部 4 層約占可見立面高度的 **三分之二**，下部 2 層約占 **三分之一**，不另把頂簷計作一層。右側同一照片平面中，近端玻璃、中央石材翼、遠端玻璃的投影寬度約為 **3：5：2**；這只用來判斷構圖與量體輕重，不能直接轉為公尺或忽略透視造成的遠近縮短。

R02 入口近景可補證基座與深窗洞，但照片上緣裁切，不能獨立據它數全棟樓層。側翼退縮、樓板標高、窗洞尺寸和實際層高仍須圖面或測量；不得藉此觀察推導未見區域。

總計 **6,703,583 bytes（6.70 MB）**，未超過 10 MB。全部為未修改的 1K Radiance HDR。選擇 1K 控制下載與常駐環境資源成本；它可用於環境照明，不能宣稱與更高解析天空／鏡面反射完全相同。現有 Phase 5A runtime 預載公園日間／黃昏／夜間 3 張並快取 PMREM 到 HQ dispose，以避免切換時重新載入；城市日間那張僅為候選資產，未被 preset 使用。這不是僅單張按需常駐，實際 GPU 成本須另行測試。

完整作者、原始下載 URL、官方 API metadata URL、授權、MD5、SHA-256、bytes、解析度與取得時間見 [`manifest.json`](../../assets/environment/hq5-lighting/manifest.json)。下載規則為官方 metadata 指向的 `https://dl.polyhaven.org/file/ph-assets/HDRIs/hdr/1k/<id>_1k.hdr`，未以未知第三方鏡像替代。

### 本次實際檢查

1. 四個檔案下載 bytes 與官方 metadata 一致，MD5 相符，另計算 SHA-256。
2. 檢查 Radiance 格式與 1024×512 header，並使用專案 Three.js `RGBELoader.parse()` 在 Node CPU 完整解碼：四個檔案皆輸出 2,097,152 個 Uint16 樣本。
3. 已目視四張官方全景預覽；預覽留在 `../phase5-work/references/*-preview.png`，不重新散布網站預覽圖。
4. **本素材研究階段未執行 GPU／PMREM／Three.js 場景渲染或效能測試。** 可用的檔案與 CPU 解碼，不代表場景整合、曝光、色彩或視覺品質已 PASS；後續整合實測與最終狀態見 [`TEST-RESULTS.md`](TEST-RESULTS.md)，不以本段素材查核描述整輪交付的測試狀態。

HDRI 是通用光照／反射素材，不是行善路 158 號現場 360° 攝影。不應將倫敦街道、歐洲辦公建築或湖畔全景作為未標示的真實台北背景；可將環境反射與場景背景分離，維持 HQ 畫面中的場址描述正確。
